# Development OTA Server

This development server replaces the production nginx server for local development. It watches the `src/` directory for changes and automatically generates the `versions.json` manifest in memory.

## Features

- **File Watching**: Monitors `src/` directory for changes to `.py` and `.mpy` files
- **Automatic Manifest Generation**: Creates `versions.json` in memory when files change
- **OTA Endpoint Mapping**: Maps `/ota/` requests to `src/` directory
- **Version Management**: Uses file modification times as versions for development
- **MD5 Checksums**: Calculates MD5 hashes for file integrity checking

## Usage

### Quick Start

1. **Windows**: Double-click `start_dev_server.bat`
2. **Linux/macOS**: Run `./start_dev_server.sh`

### Manual Start

```bash
python3 dev_ota_server.py --src-dir src --host 127.0.0.1 --port 8000
```

### Command Line Options

- `--src-dir`: Directory to watch for changes (default: `src`)
- `--host`: Host to bind to (default: `127.0.0.1`)
- `--port`: Port to bind to (default: `8000`)

### start_dev_server.* Defaults and Overrides

The helper scripts now default to binding to `127.0.0.1` for safety (local only).

You can override host/port with environment variables:

- `DEV_SERVER_HOST`
- `DEV_SERVER_PORT`

Examples:

```bash
DEV_SERVER_HOST=0.0.0.0 DEV_SERVER_PORT=8000 ./start_dev_server.sh
```

## Endpoints

- `http://localhost:8000/ota/versions.json` - Returns the generated manifest
- `http://localhost:8000/ota/<file_path>` - Serves files from `src/` directory

## Development vs Production

### Development (this server)
- Files served from `src/` directory
- Manifest generated in memory using file modification times
- Automatic regeneration on file changes
- Uses `http://localhost:8000/ota` base URL

### Production (nginx)
- Files served from `/var/www/ota/` directory
- Manifest generated by CI pipeline using git commit timestamps
- Static files deployed via GitHub Actions
- Uses `http://badge.cactuscon.com/ota` base URL

## How It Works

1. **File Monitoring**: The server watches all `.py` and `.mpy` files in the `src/` directory
2. **Change Detection**: When files are modified, the manifest is regenerated
3. **Version Assignment**: File modification times are used as version numbers
4. **MD5 Calculation**: Each file's MD5 hash is calculated for integrity checking
5. **Manifest Generation**: A `versions.json` manifest is created in memory
6. **HTTP Serving**: The server responds to OTA requests from the badge

## Badge Configuration

In your badge config, ensure development mode is enabled and the OTA base URL
points at your dev server host/port reachable from the badge on your network.

```python
DEVELOPMENT = True
OTA_BASE_FILE_URL = "http://localhost:8000/ota" if DEVELOPMENT else "http://badge.cactuscon.com/ota"
OTA_MANIFEST_URL = "http://localhost:8000/ota/versions.json" if DEVELOPMENT else "http://badge.cactuscon.com/ota/versions.json"
```

```json

  "files": [

      "version": 1704067200,
      "md5": "d41d8cd98f00b204e9800998ecf8427e"
    },
    {

      "version": 1704067150,

```

## Troubleshooting

- **Port in use**: Change the port with `--port` option
- **Permission denied**: Run as administrator/sudo if binding to port < 1024
- **Files not updating**: Check that files are actually being modified (save in editor)
- **Badge can't connect**: Ensure firewall allows connections on the chosen port

## CI Comparison

This development server mimics the CI pipeline logic from `.github/workflows/badge-ci.yml`:

- **File Discovery**: Same logic for finding `.py`/`.mpy` files
- **MD5 Calculation**: Same MD5 hashing algorithm
- **Manifest Structure**: Same JSON structure as CI-generated manifest
- **Version Logic**: Uses mtime instead of git commit timestamps for development
